LoadConfigStores calls Normalize on each layer as it loads, before mergeRootConfigs runs Merge. Merge gives the later layer's values precedence, so a default Normalize fills into an empty project-layer field reads as a value the project set, and replaces the CLI layer's real value. Found while writing examples/comprehensive in E-2650: Normalize set Theme to light when empty, the CLI file set theme dark, the project file set only editor, and LoadConfig returned theme light. The example now sets no defaults in Normalize and says why in a comment, which works around the problem rather than fixing it. Merge cannot tell a default from a value the file set, so every app that defaults in Normalize and loads more than one layer is exposed. Related: E-2514 explores replacing Normalize with a post-load step.
