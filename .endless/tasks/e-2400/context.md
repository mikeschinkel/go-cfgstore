mergeRootConfigs in config_stores.go calls Merge across the loaded layers and keeps the result in rc, then returns prc = rcMap[dirType]: the last layer as loaded, unmerged. Whenever more than one layer exists, the merge is computed and thrown away, so LoadDefaultConfig returns the project layer alone and every CLI-layer value is lost. A probe confirmed it: a CLI-layer value resolved correctly from a directory with no project config, and was lost from any directory holding one, while the config type's own Merge, called directly, kept it.
