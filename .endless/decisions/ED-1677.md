When an app's settings come from several config files (for example a user-wide file, then a project file), go-cfgstore starts with one empty value, fills in the app's defaults, then reads each file into that same value in order: a setting a file leaves out keeps its earlier value, and a setting it includes replaces it, even with false, 0 or empty. Before that, it reads and checks each file on its own, so one run reports every problem in every file, each naming its file. This replaces reading each file into a separate value and having the app copy settings across one at a time, which could not tell an omitted setting from one set to false, so a later file could not turn a setting off and a default could replace an earlier file's real setting. Rejected: wrapping every setting in a type that records whether the file contained it, because all app code would read and assign through the wrapper, and rules for combining lists and maps would live in unchecked struct-tag text.
